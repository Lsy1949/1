# 成长积分机制（心理测评）

> 适用模块：测评中心 / 成长看板 / 我的
> 文档性质：业务规则与机制说明（非代码文档）
> 版本：v1
> 最后更新：2026-11-17

---

## 1. 一句话定义

**成长积分是一套可追溯的行为激励账本**：每完成一次有效测评记一笔 +10 的流水，余额等于全部流水之和；积分只用于成长度量、等级与权益解锁，不可提现、不设排行榜。

| 项目 | 规则 |
|---|---|
| 数据模型 | 账户（余额快照）+ 流水（每一次加减分凭据） |
| 基础分值 | 完成一次有效测评 +10 |
| 计分上限 | 每日最多 3 次计分；单日封顶 40 分 |
| 幂等 | 同一测评结果只入账一次 |
| 扣分 | 无惩罚性扣分；清空历史也不扣分 |
| 上限 | 账户上限 999,999（保护阈值，正常使用不可达） |
| 用途 | 等级、权益解锁、成长档案展示 |
| 数据范围 | 服务端账户（当前由本地 mock 模拟） |

---

## 2. 设计原则

1. **可解释**：任何一分都能对应到一条流水（时间、来源、变动后余额），不允许出现「凭空 +10」。
2. **不可刷**：幂等 + 每日次数上限 + 单日分值封顶 + 响应时长风控，四层约束。
3. **不掉级**：等级按「累计获得」计算，而非当前余额；将来开放消耗也不会降级。
4. **不惩罚**：清空记录、删除记录都不扣已得积分，避免用户因整理数据而受损。
5. **单一真相源**：所有展示位（Hero、看板、我的）读同一份账户数据，禁止前端各自推算。
6. **前端只渲染**：计分、等级、进度、勋章解锁等规则全部由服务端计算，前端只做文案映射与展示。

## 3. 核心模型

### 3.1 三个对象

| 对象 | 含义 | 关键字段 |
|---|---|---|
| 积分账户 | 用户的余额与累计快照 | 余额、累计获得、累计消耗、等级、等级更新时间 |
| 积分流水 | 一次加减分的不可变凭据 | 类型（获得/消耗/撤销）、规则标识、变动值、变动后余额、关联业务（测评结果/兑换单）、幂等键、时间 |
| 规则表 | 可配置的规则定义 | 规则标识、触发条件、分值、上限、冷却、启停开关 |

### 3.2 不变式（必须始终成立）

1. **余额 = 全部流水变动值之和**，每日对账任务校验，不一致即告警。
2. **余额不允许为负**，任何消耗前先校验余额。
3. **同一幂等键只能成功入账一次**，覆盖重复提交、网络重试、并发双击。
4. **流水不可修改**，撤销只能追加一条反向流水。
5. **规则变更不追溯历史流水**，已发分值不重算，除非显式发起重算任务。

## 4. 获取规则

> 分值、上限、冷却均为服务端可配置项，前端不写死。

| 规则标识 | 触发条件 | 分值 | 上限 / 冷却 | 设计意图 |
|---|---|---|---|---|
| `assess.complete` | 完成并交卷一次有效测评 | +10 | 每日最多计 3 次 | 鼓励完成，但抑制无脑刷分 |
| `assess.first_scale` | 首次完成某个量表 | +5 | 每个量表一次性 | 鼓励拓宽量表面 |
| `assess.category_new` | 首次覆盖一个新分类 | +10 | 最多 6 次（6 个分类） | 鼓励跨维度探索 |
| `assess.retake` | 同量表重测，距上次 ≥ 7 天 | +5 | 同量表每 7 天最多 1 次 | 满足「看变化」需求，同时防刷 |
| `assess.weekly_streak` | 连续 2 个自然周各有 ≥1 次测评 | +15 | 每自然周结算 1 次 | 轻量连续性激励，不做每日打卡 |
| `assess.milestone_5` | 累计有效完成 5 次 | +20 | 一次性 | 里程碑 |
| `assess.milestone_10` | 累计有效完成 10 次 | +30 | 一次性 | 里程碑 |
| `assess.milestone_20` | 累计有效完成 20 次 | +50 | 一次性 | 里程碑 |
| `assess.milestone_30` | 累计有效完成 30 次 | +100 | 一次性 | 里程碑 |

### 4.1 有效测评的定义

一次提交必须同时满足以下条件才触发 `assess.complete`：

1. 所有题目作答完毕并提交成功；
2. 服务端计分成功并写入历史记录；
3. 未被风控标记为无效（见 6.3）；
4. 未超过当日计分上限。

不满足 1–3 的提交**仍可保存历史与结果报告**，只是记 0 分，并在结果页说明原因，避免「白做」。

### 4.2 积分曲线（参考）

| 用户画像 | 行为 | 首月积分 |
|---|---|---|
| 轻度 | 测 2 个量表，覆盖 1–2 类 | 约 40 |
| 常规 | 测 5 个量表，覆盖 3 类，1 次重测 | 约 130 |
| 活跃 | 每周 1–2 次，覆盖 5 类，含连续周 | 约 240–280 |

## 5. 等级与权益

### 5.1 等级阈值（按累计获得计算）

| 等级 | 累计获得积分 | 大致对应 | 权益（解锁型，不消耗积分） |
|---|---|---|---|
| Lv.1 起步 | 0 | 新用户 | 基础测评与结果报告 |
| Lv.2 探索 | 80 | 约 5–6 次 | 历次对比视图（同量表趋势） |
| Lv.3 稳定 | 200 | 约 12–15 次 | AI 深度解读，每周 1 次 |
| Lv.4 深入 | 360 | 约 22–25 次 | 专属测评主题 / 成长证书 |
| Lv.5 精通 | 560 | 约 35 次 | 年度成长报告 + 徽章展示 |

**关键规则**：等级看累计获得，不看余额。即使将来开放积分消耗，等级也不会下降。

### 5.2 等级进度

- 进度 =（累计获得 − 本级起点）÷（下一级起点 − 本级起点），四舍五入，封顶 100%。
- 满级显示「已满级」，不再提示距下一级。
- 等级变化需落一条「等级变更」事件，供「我的」做动效与通知。

### 5.3 勋章（与等级并行，互不替代）

| 勋章 | 解锁条件 |
|---|---|
| 初次测评 | 完成 ≥ 1 次 |
| 跨界探索 | 覆盖 ≥ 2 个分类 |
| 情绪关注 | 测过心理健康类量表 |
| 生涯探索 | 测过生涯发展类量表 |
| 深度测评 | 完成 ≥ 3 次 |
| 测评达人 | 完成 ≥ 5 次 |

> 等级表达「长期阶段」，勋章表达「具体成就」。勋章判定用次数与分类覆盖，与积分数值无关。

## 6. 严谨性：防刷、上限与一致性

### 6.1 幂等

- 每次提交生成唯一 `resultId`，账本幂等键为 `result:{resultId}`。
- 重复请求（网络重试、双击、刷新重放）只入账一次。
- 一次性规则幂等键为 `rule:{ruleKey}:{scope}`，例如 `rule:assess.first_scale:phq9`。

### 6.2 三重上限

| 上限 | 默认值 | 目的 |
|---|---|---|
| 单日计分次数 | 3 次 | 防止一天内刷分 |
| 同量表冷却 | 7 天 | 防止单量表刷分 |
| 单日积分上限 | 40 分 | 兜底防止规则叠加爆分 |

超出上限时：**历史照常记录、报告照常生成，只是不再加分**，并在结果页提示（例：「今日计分已达上限，本次仍已计入历史」）。

### 6.3 风控标记（只影响计分，不影响使用）

| 信号 | 处理 |
|---|---|
| 作答时长 < 题数 × 2 秒 | 标记 `suspicious_fast`，本次不计分（仍出报告） |
| 同一量表 1 小时内提交 ≥ 3 次 | 标记 `burst`，当次之后不再计分 |
| 答案全选同一选项 | 标记 `flat_answers`，只提示不作废，避免误伤真实用户 |

> 原则：风控只影响积分，不影响用户查看自己的报告。

### 6.4 撤销与回滚

| 场景 | 处理 |
|---|---|
| 删除单条历史 | 追加撤销流水（-10）；关联的一次性奖励不撤销，避免连锁回退 |
| 清空全部历史 | **不扣分**，成就与记录解耦 |
| 服务端漏记 | 补偿队列按 `resultId` 重放，幂等保证不重复 |
| 规则配置错误多发 | 由运维发起重算任务，只追加调整流水，不删原记录 |

### 6.5 账户初始化

首次进入测评模块时，按已有历史记录初始化账户：每有一条记录折算 10 分，生成一笔「历史记录初始化」流水；无记录则初始为 0。初始化完成后写入标记，不重复执行。

## 7. 展示规则

| 位置 | 展示 | 数据来源 |
|---|---|---|
| 测评中心 Hero | 量表总数、已完成次数、成长积分、月度目标百分比 | 目录接口 + 账户接口 |
| 成长看板 · 概览 | 累计测评、覆盖分类、平均得分、活跃天数、月度目标 | 账户接口（看板聚合接口） |
| 成长看板 · 分析 | 六维雷达、情绪趋势、分类分布、AI 洞察、进步对比、智能推荐 | 看板聚合接口 |
| 我的 · 档案 | 余额、累计获得、等级、进度条、距下一级、加入日期、成长状态 | 账户接口 |
| 我的 · 积分明细 | 最近 10 条流水：来源 / 时间 / +N / 变动后余额 | 账户接口 |
| 我的 · 测评台账 | 全部历史记录：查看 / 重测 / 按量表筛选 / 导出 CSV / 清空 | 历史接口 |
| 我的 · 积分规则 | 规则摘要与上限说明 | 与本文档同源 |

**文案要求**：每条流水必须有可读来源，例如「完成抑郁自评 PHQ-9 +10」「首次探索「人际关系」分类 +10」「连续两周测评 +15」，不允许只显示「+10」。

### 7.1 「我的」与「成长看板」的职责划分

两个页签面向不同问题，不允许重复承载同一块内容：

| 维度 | 我的 | 成长看板 |
|---|---|---|
| 回答的问题 | 我是谁、我积累了什么 | 我怎么样、在往哪里走 |
| 定位 | 档案 · 资产 · 记录 | 分析 · 趋势 · 建议 |
| 核心内容 | 积分余额与累计获得、等级与进度、勋章、加入日期、成长状态、积分明细、完整测评台账（查看 / 重测 / 筛选 / 导出 / 清空） | 累计测评、覆盖分类、平均得分、活跃天数、月度目标、六维雷达、情绪趋势、分类分布、AI 洞察、进步对比、智能推荐 |
| 不出现 | 任何趋势图、雷达图、推荐、AI 洞察 | 积分余额、等级进度、勋章、积分流水、逐条记录表格 |
| 数据性质 | 「资产与凭据」——只增不减、可回看 | 「洞察与建议」——随记录变化重新计算 |

**执行约定**

1. 新功能先问归属：是「我的东西」还是「对我的分析」，按上表落位，不两边都放。
2. 两个页签共享同一份历史与账户数据，但**不共享展示模块**：台账只在「我的」，图表只在「看板」。
3. 允许跨页签引导（如「我的」底部提示「去看成长分析」），但不复制内容。

### 7.2 前后端职责边界

**原则：前端只做「取值 + 文案映射 + 条件渲染 + 格式化」，不承载业务规则。**

| 允许（展示层） | 禁止（必须服务端返回） |
|---|---|
| i18n 文案、日期/数字格式化 | 计分、等级、进度、阈值判断 |
| 加载 / 错误 / 空态切换 | 聚合统计（次数、天数、均值、分布、趋势） |
| 按服务端标识取图标与颜色 | 勋章 / 权益 / 资格解锁判断 |
| 把接口数组直接喂给图表 | 推荐规则、洞察文案变体选择 |
| 用户交互态（展开、选中页签） | 排序筛选规则、任何兜底推导 |

## 8. 异常与边界清单

| # | 场景 | 期望行为 |
|---|---|---|
| 1 | 双击交卷 | 只入账一次（幂等） |
| 2 | 交卷成功但响应超时后重试 | 命中幂等键，返回同一结果，不重复加分 |
| 3 | 当天第 4 次测评 | 正常出报告与历史，提示「今日计分已达上限」 |
| 4 | 同量表 3 天内重测 | 历史累加，不触发 `assess.retake` |
| 5 | 首次覆盖新分类 | 与基础分同时入账（两笔流水） |
| 6 | 里程牌与基础分同时达成 | 各一笔流水，明细可分别查看 |
| 7 | 清空历史 | 历史清空、报告不可查看；余额与等级不变 |
| 8 | 换设备登录 | 余额以服务端账户为准 |
| 9 | 离线提交 | 本地排队，联网后补交，幂等避免重复 |
| 10 | 规则被关闭 | 该规则不再产生新流水，历史流水保留 |
| 11 | 时区差异 | 统一按服务端自然日切分，避免跨时区重复计入 |
| 12 | 余额溢出 | 账户上限 999,999，超出拒绝入账并告警 |

## 9. 验收用例（Given / When / Then 摘要）

1. **基础分**：新用户完成 1 次有效测评 → 余额 +10，明细出现「完成 XX 量表 +10」。
2. **幂等**：同一 `resultId` 提交两次 → 只 +10 一次。
3. **每日上限**：当日已计分 3 次后再完成 1 次 → 余额不变，历史 +1，结果页提示上限。
4. **冷却**：3 天前测过 PHQ-9，今天再测 → 只加基础分，无重测奖励。
5. **首次量表**：首次完成 GAD-7 → +10 与 +5 两笔流水。
6. **新分类**：已测心理健康类后首次测生涯类 → 触发 `category_new`。
7. **连续周**：上周与本周各有 1 次 → 本周结算 +15，仅一次。
8. **里程碑**：累计 4 次后完成第 5 次 → +10 与 +20。
9. **清空历史**：余额 130 时清空 → 历史为 0，余额仍 130。
10. **账户初始化**：已有 13 条历史 → 首次进入余额 130，且只初始化一次。
11. **风控**：9 题量表 10 秒内交卷 → 出报告但不加分。
12. **等级不变**：Lv.4 用户消耗 30 分 → 等级仍 Lv.4。

## 10. 埋点与监控

| 事件 | 用途 |
|---|---|
| `points.earn`（规则、分值、余额） | 观察各规则贡献占比，判断是否通胀 |
| `points.cap_hit`（日上限 / 冷却） | 评估上限是否过严 |
| `points.risk_flagged`（类型） | 调整风控阈值 |
| `points.reconcile_mismatch` | 账本对账异常告警 |
| `level.up` | 等级转化率与权益使用率 |

健康指标建议：人均周获得 20–60 分；`cap_hit` 占比 < 5%；`risk_flagged` < 2%；对账不一致 = 0。
